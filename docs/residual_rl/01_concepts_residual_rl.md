## A one-screen RL primer

Pick the smallest possible vocabulary:

- **State** `s`: what the agent observes right now. Here, three RGB images and a 24-D proprioception vector.
- **Action** `a`: what the agent does. Here, a 24-D joint+finger target (see [05_policy_protocol.md](../05_policy_protocol.md)).
- **Policy** `π(a | s)`: a function that maps state to action. We use deterministic policies in this branch, so it is just `a = π(s)`.
- **Reward** `r`: a scalar that says how good the last action was, fed in from the reward labeler. Bigger is better.
- **Return**: the cumulative discounted reward. Formally `R = r_t + γ·r_{t+1} + γ²·r_{t+2} + …`. The discount factor `γ ∈ [0, 1)` ([`Critic_Trainer.discount_factor` default `0.99`](https://github.com/KyunHwan/trainer/blob/3ca051a256c9068f77b556df98f538d9a6185ccf/experiment_training/components/trainer/reinforcement_learning/resfit/utils/critic_trainer.py#L14)) makes the agent prefer rewards sooner.
- **Q-function** `Q(s, a)`: an estimate of the return you will get if you take action `a` in state `s` and then follow the current policy afterwards. We train a neural net to approximate this.
- **On-policy vs off-policy**: on-policy means the data you train on was generated by the current policy. Off-policy means it might have come from older policies (or from a teleop operator). Replay buffers go hand-in-hand with off-policy methods because samples in the buffer were produced by *older* versions of the policy.

That is the entire vocabulary needed below. If you want it in textbook form, the Sutton and Barto book is the canonical reference, but it is not required for this branch.

## What "residual" adds

A *residual policy* sits on top of an existing **base policy** and only learns the *delta*:

```
a_final = π_base(s) + π_residual(s, π_base(s))
```

The base policy stays fixed; only the residual is trained. The residual is bounded (a `tanh` followed by a `0.25` scale, see [`Residual_Actor.forward`](https://github.com/KyunHwan/trainer/blob/3ca051a256c9068f77b556df98f538d9a6185ccf/policy_constructor/model_constructor/blocks/experiments/resfit/residual_actor.py#L188-L224)) so the corrections cannot blow up. The Q-function is trained to predict the return of the *combined* action, not the base alone.

The exact code line — the place where the addition happens at runtime — is:

```python
# env_actor/auto/inference_algorithms/rtc/actors/control_loop.py:204
action = residual_action + base_policy_action
```

(see [`control_loop.py:204`](../../env_actor/auto/inference_algorithms/rtc/actors/control_loop.py#L204))

## A toy worked example

Pseudocode for a stripped-down residual loop, with the actual repo's names commented inline:

```python
# pseudocode — NOT the real implementation
base_policy   = load_pretrained_vla()    # the DSRL-OpenPI policy
residual      = MLP(state_dim + action_dim, action_dim)  # Residual_Actor
q             = MLP(state_dim + action_dim, 1)            # Q_Function
q_target      = copy(q)                                   # Polyak-averaged target

for episode in roll_out_forever():       # ControlLoop process
    for s in episode:
        a_base = base_policy(s)          # InferenceLoop wrote this into shm
        delta  = residual(s, a_base)     # ResidualPolicy.inference()
        a      = a_base + delta          # the line above
        s_next, r = env.step(a)
        replay_buffer.add(s, a, a_base, r, s_next)  # ResfitReplayBufferActor.add

# Trainer process, runs in parallel:
for step in trainer_steps:
    batch = replay_buffer.sample(B)             # B chunked samples
    # --- critic update ---
    with torch.no_grad():
        a_base_next = batch["base_policy_action"][..., t+1]
        a_next      = a_base_next + residual(batch.state_next, a_base_next)
        td_target   = R(batch.reward_chunk, γ) + γ**H * q_target(batch.state_next, a_next)
    q_loss = MSE(q(batch.state, batch.action[..., t]), td_target)
    q_loss.backward(); q_opt.step()

    # --- target Q update ---
    polyak_update(q_target, q, τ=0.005)

    # --- actor update (every 10 critic steps) ---
    if step % 10 == 0:
        a_combined = batch.base_policy_action[..., t] + residual(batch.state, batch.base_policy_action[..., t])
        actor_loss = -q(batch.state, a_combined).mean()  # MAXIMIZE Q
        actor_loss.backward(); actor_opt.step()

    if step % save_every == 0:
        push(residual.state_dict)        # via StateManagerActor -> ControlLoop
```

The real code looks busier because:
1. It runs across three machines under Ray.
2. The base policy emits an *action chunk*, not a single action, so chunks must be aligned.
3. The Q-function is an *ensemble* of 10 small MLPs ([`Q_Function`](https://github.com/KyunHwan/trainer/blob/3ca051a256c9068f77b556df98f538d9a6185ccf/policy_constructor/model_constructor/blocks/experiments/resfit/residual_q_function.py#L131-L264)) and the critic loss randomly subsamples half of them per gradient step ([`Q_Function.forward` with `critic=True`](https://github.com/KyunHwan/trainer/blob/3ca051a256c9068f77b556df98f538d9a6185ccf/policy_constructor/model_constructor/blocks/experiments/resfit/residual_q_function.py#L236-L264)).
4. Until the trainer has pushed its first set of weights, the control loop emits a *uniform-random* residual in `[-0.08, 0.08]` so that exploration starts immediately ([`control_loop.py:200-204`](../../env_actor/auto/inference_algorithms/rtc/actors/control_loop.py#L200-L204)).

## Why residual RL is attractive here

| Concern | Plain fine-tuning of the VLA | Residual RL on this branch |
|---|---|---|
| Risk of destroying base capabilities | High — a single bad gradient on a 7B-parameter model can break weeks of pre-training. | Zero — base weights are frozen. |
| Wall-clock cost per gradient step | Several seconds on a single GPU. | Tens of milliseconds for an MLP head. |
| Sample efficiency in deployment | Needs a lot of new demonstrations. | Q-learning on chunked rewards reuses each rollout many times. |
| Failure mode | Subtle degradation across all skills. | Residual saturates at ±0.25 — failures are bounded. |

The trade-off is **expressivity**: a 5-layer MLP residual cannot rewrite high-level strategy. It is suited for "smooth out the last 10%" tasks, not "learn a new skill."

## Common misconceptions

- **"The residual replaces the base."** No. The control loop literally adds them: `action = residual_action + base_policy_action` ([`control_loop.py:204`](../../env_actor/auto/inference_algorithms/rtc/actors/control_loop.py#L204)). If the residual is exactly zero, the system reduces to "run the base policy."
- **"The base policy is being fine-tuned too."** No. On the inference side, the base policy is loaded from a fixed checkpoint and never receives a weight update; the control loop polls `policy_state_manager` only when `use_residual_rl=True`, and the inference loop only when `use_residual_rl=False` (see [`control_loop.py:115-127`](../../env_actor/auto/inference_algorithms/rtc/actors/control_loop.py#L115-L127) and [`inference_loop.py:98-109`](../../env_actor/auto/inference_algorithms/rtc/actors/inference_loop.py#L98-L109)). On the trainer side, the residual actor has `online_update: true` and the Q-function has `online_update: false`, so *only* the residual actor's weights are ever pushed back to inference ([resfit.yaml:13-15](https://github.com/KyunHwan/trainer/blob/3ca051a256c9068f77b556df98f538d9a6185ccf/experiment_training/reinforcement_learning/resfit/online_rl/resfit.yaml#L13-L15)).
- **"The actor loss minimizes a behavioral-cloning term."** No. The actor loss is `-Q(s, a_combined).mean()` — it maximizes the Q-value of the combined action ([trainer:actor_trainer.py:43](https://github.com/KyunHwan/trainer/blob/3ca051a256c9068f77b556df98f538d9a6185ccf/experiment_training/components/trainer/reinforcement_learning/resfit/utils/actor_trainer.py#L43)). There is *no* L2 loss against an action target on this branch.
- **"The reward is the action error."** No. The reward comes from the reward labeler (auto or manual). The actor/critic do not see ground-truth actions during the RL loss.
- **"The Q-function output is calibrated."** It is not. The 10-MLP ensemble averages plain scalars; the magnitude depends on the reward labeler's range and `γ`. Watch the *trend* of `Residual Q Loss`, not the absolute value.
- **"Each step is a fresh `s, a, r, s'` tuple."** Closer to false than true. The replay buffer stores per-step rows but the sampler emits **chunked windows** (length 4 anchored at index 0 by default, see [`resfit_replay_buffer.py:39-50`](../../data_bridge/resfit_replay_buffer.py#L39-L50) and [05_config_and_hyperparameters.md](./05_config_and_hyperparameters.md)). The actor sees the *current* state and base action; the critic uses a *future* state and base action to compute the TD target.
